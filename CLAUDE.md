# Морс (sober)

Мобильное приложение для отказа от алкоголя, Android-first. Продуктовая спека: [docs/idea.md](docs/idea.md), ресерч конкурентов: [docs/competitors.md](docs/competitors.md).

Статус: есть онбординг (первый экран с иконкой продолжением сплэша и входом, дисклеймер, скрининг, старт, траты, причины, напоминания, подсказка про автозапуск), на "Сегодня" счетчик трезвых дней, полоска последних 7 дней, "Сэкономлено" и причина дня (оформлены по макету), на "Прогрессе" лучший стрик и всего трезвых, итоги дня (вечерний опрос, после сохранения кнопка становится галочкой с искрами и вибрацией и экран закрывается сам), модалка срыва, на "Прогрессе" календарь месяца, тап по дню открывает модалку карточки дня (срывы с удалением, вечеринка, итоги дня с правкой за прошлые дни, достижения дня) и короткий блок достижений медалями с экраном "все", тап по медали открывает карточку медали с анимацией, новые медали празднуются, два таба ("Сегодня" и "Прогресс"), настройки хабом (старт и траты, мои причины, уведомления, экспорт и импорт, о приложении со строкой "Журнал": локальный журнал ошибок и событий, сохранить или отправить файлом), экран ошибки рендера с "Заново" вместо белого экрана, экспорт всех данных в JSON (сохранить на телефон или отправить через "Поделиться") и импорт с полной заменой (и из настроек, и ссылкой "Восстановить из файла" на первом шаге онбординга), режим "иду в компанию" с карточкой "как прошло?" на "Сегодня", локальные уведомления (итоги дня, дни риска, "как прошло?"). На "Прогрессе" превью статистики и экран "Статистика" (инфографика за последние 30 дней или прошлый месяц: тяга по дням недели, настроение, топы трудностей и помощи, срывы с их разбором, вечера в компании). Есть виджет 1x1 для Android с текущим стриком, в двух видах (карточка и чернила). Визуальная база есть (палитра "Чернила", Manrope, свои кнопки).

## Стек

- TypeScript, Expo SDK 57 (React Native 0.86, React 19), expo-router.
- `expo-sqlite`, без ORM. Миграции через `PRAGMA user_version`, только аддитивные: новые таблицы и колонки (с `NULL` или default), без удаления и переименования. После отката OTA старый бандл работает на схеме новее себя, `migrate` тогда ничего не делает.
- `zod` (JS-only, пересборка не нужна): схемы строк базы, тип строки - `z.infer` от схемы. На Hermes работает и с JIT (проверено), `jitless` не нужен.
- `@react-native-community/datetimepicker` для выбора даты и времени. На Android открываем императивно через `DateTimePickerAndroid.open`.
- `expo-notifications` для локальных напоминаний с кнопками действий (categories), В Expo Go на Android не работает (падает уже на импорте), поэтому разработка идет в development build.
- Шрифт Manrope из `@expo-google-fonts/manrope`, грузится в рантайме через его `useFonts` (под капотом `expo-font` из `expo`). Прямой зависимости `expo-font` и его плагина в `app.json` нет: `npx expo install expo-font` дописывает плагин, а это нативное изменение.
- `expo-file-system` (прямая зависимость, нативно он и так в сборке через `expo`): файл экспорта в `Paths.cache` и системный выбор файла для импорта (`File.pickFileAsync`), плагин не нужен. `expo-sharing`: отдает файл экспорта в "Поделиться". `@react-native-documents/picker` (`saveDocuments`): системный диалог "Сохранить как" для экспорта на телефон, в нем доступны Download и корень памяти (выбор папки из `expo-file-system` туда не пускает, а `expo-intent-launcher` не отдает адрес созданного файла).
- `expo-haptics`: вибрация при празднике медали.
- `expo-task-manager`: фоновая задача уведомлений (`Notifications.registerTaskAsync`, `features/notifications/model/background.ts`, регистрация в корневом `index.ts`). На Android она срабатывает по кнопке без открытия приложения, даже когда процесс выгружен: так "Не иду" закрывает уведомление дней риска. Плагин не нужен.
- `expo-updates` и EAS Update: OTA-обновления JS. Проверка при запуске (`ON_LOAD`), скачивание в фоне, применение при следующем запуске, откат упавшего на старте бандла - все делает библиотека по `updates` в `app.json`, своего кода проверки нет. `runtimeVersion` - политика `fingerprint`: любое нативное изменение отрезает старые сборки от новых бандлов. `.fingerprintignore` исключает манифесты библиотек в `node_modules`: локальный `yarn android` правит их на месте, и без этого `eas build --local` падает на несовпадении runtime version на маке и в сборке. Каналы в `eas.json`: `preview` и `production` (профиль под Google Play, AAB); в dev-сборке `app.config.ts` ставит `updates.enabled: false`. Обновления не подписаны: code signing в EAS Update только на платном тарифе, защита - HTTPS и 2FA на аккаунте Expo. Экспорт `eas update` идет в `.expo/update`, не в `dist/`: он очищает папку, а там лежат APK. Публикуем в `preview`, проверенное промоутим в `production`. `shared/lib/updates.ts`: `logUpdateLaunch()` из корневого `index.ts` пишет событие `updates` в журнал при смене бандла (прошлый id в файле `Paths.document/update-id`, не в `settings`: тот уходит в экспорт), `currentUpdate()` - id и дата для "О приложении". Процесс публикации и отката - в README.
- `expo-splash-screen`: сплэш - иконка медальоном на фоне темы (цвета повторены в `app.json`, рядом комментарий в `theme.ts`), `_layout.tsx` держит его до загрузки шрифтов. Иконка и сплэш рисуются в SVG (`assets/src/`, холст 108), PNG в `assets/` собирает `yarn icons`, руками PNG не правим. В foreground и монохроме adaptive icon знак уменьшен на 2/3: лаунчер показывает центральные 72 из 108. Фон adaptive icon - картинка (`android-icon-background.svg`, в `app.json` `backgroundImage`), потому что в нем градиент; свечение в нем пересчитано под уменьшенный знак.
- `react-native-svg` для медалей достижений. Графики статистики рисуются на `View`, без SVG.
- `lucide-react-native` для иконок интерфейса (JS поверх `react-native-svg`, пересборки не требует). Напрямую импортирует только `shared/ui/Icon.tsx`, по одной иконке (`lucide-react-native/icons/<name>`): из корня пакета Metro в dev тянет все иконки.
- `react-native-android-widget` для виджета 1x1 (плагин в `app.json`: виджеты `Streak` - карточка и `StreakInk` - чернила, `updatePeriodMillis` 30 минут, превью, шрифт Manrope Bold из `node_modules`). Обработчик фоновых событий (как и фоновая задача уведомлений) регистрируется в корневом `index.ts` (он же `main` в `package.json`) до `expo-router/entry`. iOS-виджета пока нет.
- Отдельного стейт-менеджера нет: хватает React и запросов к SQLite. Добавляем только если без него станет больно.
- i18n с первого дня: ru основной, en сразу рядом.
- `expo-dev-client`: development build вместо Expo Go. Сборка через EAS (бесплатный тариф, профили в `eas.json`) или локально. Bundle id `com.berryrise.app`, slug и scheme `berryrise`. Профиль `development` в `eas.json` ставит `APP_VARIANT=development`, и `app.config.ts` делает из dev отдельное приложение: пакет `com.berryrise.app.dev`, имя и подписи виджетов с "dev", scheme `berryrise-dev`. `yarn android` и эмулятор собирают без него, под `com.berryrise.app`.

## Команды

Пакетный менеджер yarn 4 (`nodeLinker: node-modules`). Пошагово сборка и установка на телефон, эмулятор и через EAS описаны в [README.md](README.md), при изменении скриптов сборки обновляй и его.

```bash
yarn install
yarn start              # dev-сервер, на телефоне открыть в development build (не Expo Go)
yarn build:local:dev    # dev build APK локально, без квоты -> dist/berryrise-dev.apk
yarn build:local:preview # полноценный APK без dev-клиента (JS внутри, metro не нужен) -> dist/berryrise-preview.apk
yarn install:dev        # поставить dist/berryrise-dev.apk на телефон (USB или Wi-Fi), данные сохраняются; при нескольких устройствах ANDROID_SERIAL=<ip:port>
yarn install:preview    # то же для preview
yarn build:eas:dev      # dev build в облаке EAS, тратит квоту (15 в месяц)
yarn build:eas:preview  # preview в облаке EAS, тратит квоту
yarn eas <команда>      # любой eas-cli (login, init, build:list)
yarn update:preview -m "..."  # OTA-обновление в канал preview
yarn update:promote     # бандл из preview в production
yarn android            # debug-сборка, установка на эмулятор/устройство и metro (expo run:android); подпись debug-ключом, для телефона не подходит
yarn typecheck          # tsc -b: проекты app и node (tsconfig.app.json, tsconfig.node.json)
yarn test               # тесты чистой логики на jest (TZ=Europe/Berlin, чтобы ловить переход на летнее время)
yarn lint               # expo lint, предупреждения тоже валят (--max-warnings 0)
yarn lint:unused        # knip: неиспользуемые файлы, экспорты, зависимости (knip.json)
yarn lint:circular      # madge: циклические импорты в src/
yarn format             # prettier --write . (конфиг .prettierrc, .claude/ в .prettierignore)
yarn doctor             # expo-doctor
yarn audit              # уязвимости зависимостей
yarn icons              # PNG иконки, сплэша и превью виджета из assets/src/*.svg (resvg через yarn dlx); это нативное изменение, нужна пересборка
npx expo install <pkg>  # добавлять пакеты только так: подбирает версию под SDK
```

`eas-cli` не в зависимостях, а через `yarn dlx`: он пинует свои зависимости точными версиями с известными уязвимостями, и `yarn audit` в pre-push падал бы без возможности это исправить.

В yarn включен `npmMinimalAgeGate` (24 часа): версии моложе суток в карантине. Если `expo install` падает с YN0016, ставь через `yarn add` предыдущий патч. Тогда expo-doctor будет ругаться на patch mismatch, это ожидаемо, через сутки поправит `npx expo install --fix`.

Git-хуки через lefthook (`lefthook.yml`), ставятся сами на `yarn install` локальным плагином `.yarn/plugins/plugin-lefthook.cjs`. pre-commit: lint-staged (eslint --fix и prettier по застейдженным файлам, конфиг в `package.json`). pre-push: typecheck, knip, madge, тесты, audit.

knip: отдельный неиспользуемый пока экспорт помечаем `/** @public */` и на объявлении, и на реэкспорте в `index.ts`. Остальное неиспользуемое удаляем.

audit: уязвимости без исправленной версии игнорируем в `npmAuditIgnoreAdvisories` в `.yarnrc.yml`, с комментарием, почему. Устаревший eslint 9 не считаем (`--no-deprecations`): eslint-config-expo пока не работает с eslint 10.

Перед тем как считать задачу сделанной, прогоняй `yarn test`, `yarn typecheck` и `yarn lint`.

## Структура

Код в `src/` разложен по [Feature-Sliced Design](https://feature-sliced.design/). Слои сверху вниз: `app` → `pages` → `features` → `entities` → `shared`. Слой импортирует только слои ниже себя, слайсы одного слоя друг друга не импортируют. Снаружи слайса импортируем только его `index.ts`, без глубоких путей. Алиас `@/` указывает на `src/` (`paths` в `tsconfig.json`, Metro подхватывает сам).

- `src/app/` - роуты expo-router, он же FSD-слой `app`. Каждый роут - одна строка `export { XPage as default } from '@/pages/x'`. Корневой `_layout.tsx` реэкспортирует `ErrorBoundary` из `pages/error` (`ErrorPage`: пишет ошибку в журнал, сам ставит фон темы и отступ под статус-бар, потому что стоит вне навигации; "Заново" перемонтирует навигатор и открывает "Сегодня"). В `_layout.tsx` лежат навигаторы и провайдеры (`SQLiteProvider` с базой `berryrise.db` и `onInit={migrate}`, `ThemeProvider` с темой из `navigationTheme`), тема и корневой `Stack` - в отдельном компоненте `Navigation` внутри `SQLiteProvider`: тот обернут в `memo`, который не сравнивает `children`, и без своего `useColorScheme` навигация не видит смену темы, там же загрузка шрифта (до нее рендерим `null` под сплэшем, при ошибке шрифта открываемся системным) и цвет окна через `expo-system-ui`.
- Навигация: корневой `Stack`, внутри группа `(tabs)` с табами "Сегодня" (`index`) и "Прогресс". Шестеренка в шапке табов ведет на `settings` (хаб). Отдельные экраны стека: `settings/` (папка без своего layout, экраны `index`, `start`, `reasons`, `notifications`, `backup`, `about`, `log` регистрируются в корневом `Stack`), `company` (режим "иду в компанию"), `achievements` (все достижения), `insights` (статистика), `achievement/[key]` (карточка медали, прозрачная модалка без шапки), `day-review` (итоги дня), `relapse` и `day/[date]` (карточка дня из календаря) (модалки). Онбординг - группа `onboarding/` со своим `Stack` (`index` первый экран без шапки, `screening`, `warning`, `start`, `spending`, `reasons`, `notifications`, `autostart` - последний только на Xiaomi и подобных). Онбординг пройден = в `habit` есть строка: она создается на шаге `start` (или приходит из файла при восстановлении на первом шаге), а layout табов без нее делает `Redirect` на `/onboarding`. Шаги после `start` необязательные: на старте стек сбрасывается через `dismissAll`, чтобы "назад" не вернул на старт, траты становятся корнем стека, дальше шаги открываются через `push` и "назад" ведет на предыдущий шаг; конец онбординга - `replace('/')`. Тема по системе, база светлая.
- `src/pages/<экран>/` - экраны: `ui/<Name>Page.tsx`, `model/use<Name>.ts` и `index.ts`. В `onboarding` восемь страниц, в `settings` шесть (хаб, старт и траты, уведомления, экспорт и импорт, о приложении, журнал `LogPage` с `model/useLog.ts`); причины - слайс `pages/reasons`, роут `settings/reasons`. Причины в онбординге и в настройках - один блок `ReasonPicker` из `features/edit-reasons`, своих хуков сохранения у этих страниц нет.
- Компоненты маленькие, каждый делает одно или собирает несколько других; критерий - страница читается сверху вниз как список блоков. Страница раскладывается на секции в своем `ui/` (`StreakSummary`, `WeekStrip`, `Savings`, `ReasonOfDay`, `PartyGoing` (плашка идущего вечера) и `PartyCard` ("как прошло?" после ожидаемого конца) в `today`; `MonthNav`, `DayCell`, `Legend` у календаря), повторяющееся между слайсами уезжает в `shared/ui` или в `ui/` сущности (`ReasonList` в `reason`). Секция со своими данными может звать свой хук (`RepliesSection` и `useReplies` в `company`).
- Компоненты в `ui/` только рисуют: JSX, тема, стили, `Alert` подтверждений и простая навигация по кнопкам. Состояние, загрузка из базы (`useSQLiteContext`), таймеры, сохранение и навигация после него живут в хуках в `model/` своего слайса. Хук экрана с загрузкой возвращает `null`, пока данные не пришли, и готовые к показу значения и действия (`canSave`, `togglePlace`, `save`). Чистую логику без React выносим в отдельный файл в `model/` и покрываем тестом.
- `src/features/` - действия пользователя, которые затрагивают несколько сущностей. Сейчас там `delete-relapse` (мягкое удаление срыва и сброс результата связанной вечеринки в одной транзакции, хук `useDeleteRelapse` и кнопка с подтверждением), `log-party-relapse` (срыв из карточки вечеринки: запись срыва и `result = 'drank'` со ссылкой на него в одной транзакции) `edit-spending` (форма трат и пресетов напитков, общая для онбординга и настроек, без кнопки: каждое изменение пишет всю форму через очередь промисов в `useRef`, так последней в базе оказывается последняя версия; состояние формы, `clear()` и список валют в `model/useSpendingForm.ts`; хук страница зовет сама и отдает форму в `SpendingForm`, как `useReasonPicker` и `ReasonPicker`) `edit-reasons` (причины чипами, как напитки в режиме компании, общие для онбординга и настроек: `useReasonPicker` и `ReasonPicker`; готовые и свои, тап включает или выключает, выбранная встает в конец, невыбранная своя остается серым чипом, долгий тап с подтверждением убирает ее из `customReasons`; в списке свои показываются и активные строки, которых в нем нет, поэтому миграции не было; `clear()` снимает весь выбор для "Пропустить" в онбординге; экран меняется сразу, записи идут очередью) `celebrate-achievement` (новые медали: `loadAchievements` грузит историю и считает медали, им же пользуется `useProgress`; показанные - JSON-массив ключей под `seenAchievements` в `settings`; чистая `model/celebrate.ts` решает, что праздновать: нет строки - все полученные молча в показанные, в день срыва (`hasRelapseBetween` по `at` или `createdAt`) ничего не показываем и не забываем, иначе пропавшие забываем, новые - очередь в общем порядке; `useCelebrate` проверяет на фокусе "Сегодня" и "Прогресса" и отдает `check()` для ответа на вечеринку, новые сразу пишет в показанные и открывает `achievement/[key]?celebrate=1&queue=...`), `backup` (экспорт и импорт: `ExportButton` и `ImportButton`; дамп всех таблиц из `sqlite_master` как есть, с удаленными строками и `settings`; файл `{ app: 'com.berryrise.app', schemaVersion, exportedAt, tables }`, чистая `model/format.ts` - имя файла и проверка обертки; импорт через `restoreDatabase`, вставляются только колонки из `PRAGMA table_info`, ошибка схемы откатывает все; что делать после импорта (уведомления, навигация), решает страница через `onImported`, потому что фича не импортирует `notifications`) `widget` (виджет на рабочем столе: `StreakWidget` - только число в квадрате по меньшей стороне ячейки, фон `SvgWidget` по системной форме иконок (`iconMask`, запасной - скругленный квадрат), кегль - доля стороны по числу цифр, без масштаба системным шрифтом, тап `OPEN_APP`, описание для TalkBack; вид по имени виджета: `card` в цветах `palette` обеих тем с ягодной чертой, `ink` одинаковый в обеих темах, цвета иконки константами по месту; `updateWidget(db)` из приложения и `widgetTaskHandler` для фона в `model/updateWidget.tsx`; `useWidget` в корневом layout обновляет при старте и уходе в фон - этого хватает на любые записи, вызывать по месту не нужно; в фоне раз в 30 минут база открывается заново (отдельным соединением `useNewConnection`: общее из кэша expo-sqlite закрылось бы у приложения при сборке мусора), так виджет ловит полночь; каждый фоновый запуск пишет событие `widget` в журнал) и `notifications` (локальные напоминания). В `notifications`: настройки одним JSON под ключом `notifications` в `settings` (нет строки - все выключено), чистая `model/plan.ts` строит разовые уведомления на 14 дней вперед (итоги дня пропускают день с заполненными итогами по `reviewDay`, дни риска - день с вечеринкой, "как прошло?" на `expectedEndAt` идущей), `syncNotifications(db)` снимает все запланированное и ставит заново, вызовы идут очередью, заодно убирает из шторки устаревшие (`isStale` по `day`/`partyId` в `data` уведомления). Синхронизируем при старте и возврате в приложение (`useNotifications` в корневом layout, там же обработка тапов и кнопок), и после записей, которые меняют план: сохранение итогов дня, ответ на вечеринку на "Сегодня", срыв из вечеринки, удаление срыва на "Прогрессе", старт и смена конца в режиме компании, изменение настроек, импорт из файла. Новое место, которое пишет итоги или вечеринки, должно звать `syncNotifications` само. Форма `NotificationForm` (три карточки `NotificationGroup`: заголовок с переключателем, описание вида, настройки в `Collapse`) и `AutostartHint` общие для онбординга и настроек, `needsAutostartHint()` - по `Platform.constants.Manufacturer` и состоянию автозапуска: на Xiaomi/Redmi/POCO оно читается локальным Expo module `modules/autostart` (скрытая операция AppOps 10008 через рефлексию, `null` - узнать нельзя, тогда подсказка видна; без кэша, настройки уведомлений перечитывают его на фокусе и возврате в приложение), `openAutostartSettings` открывает экран автозапуска MIUI/HyperOS через `expo-intent-launcher` (по имени компонента), остальным - настройки приложения. Точных будильников нет (ни `USE_EXACT_ALARM`, ни `SCHEDULE_EXACT_ALARM`): напоминания могут опоздать на минуты, это осознанно.

- Межслойные и межслайсовые импорты - только через `@/` и `index.ts` слайса, без исключений (тесты тоже: jest знает алиас через `moduleNameMapper`). Внутри слайса - относительные пути. Глубокие `@/<слой>/<слайс>/...` и `../../../` ловит `no-restricted-imports` в `eslint.config.js`.

- `openspec/` - спеки OpenSpec: `specs/` описывает текущее поведение, `changes/` - изменения в работе, `config.yaml` - контекст и правила для артефактов. Слэш-команды и скиллы OpenSpec лежат в `.claude/`, их генерирует `openspec init`/`openspec update`, руками не правим.
- `android/` и `ios/` не коммитим, их генерирует `expo prebuild` (CNG). Нативные настройки задаются только через `app.json` и config plugins.

## Expo

- API Expo меняется от SDK к SDK. Перед работой с API сверяйся с доками своей версии: https://docs.expo.dev/versions/v57.0.0/ и https://docs.expo.dev/llms.txt.
- Разработка идет в development build (`expo-dev-client`), Expo Go не подходит: в нем на Android нет `expo-notifications`. JS-изменения подхватываются dev-сервером как обычно. После добавления или обновления пакета с нативным кодом, плагина или нативных полей `app.json` dev build нужно пересобрать: для телефона `yarn build:local:dev` и `yarn install:dev`, для эмулятора `yarn android` (или `emulator-check up`).

### Пересборки (бюджет EAS)

Бесплатный тариф EAS - 15 Android-сборок в месяц, очередь низкоприоритетная. Пересобираем как можно реже.

- Нативное изменение = все, что не подхватит dev-сервер: новый, удаленный или обновленный пакет с нативным кодом (в том числе `npx expo install --fix` и обновление SDK), config plugin, нативные поля `app.json` и `app.config.ts` (`android.*`, `ios.*`, `plugins`, `permissions`, `scheme`, иконка, splash), `eas.json`. Изменения только в JS/TS и ассетах, которые грузит Metro, пересборки не требуют.
- Каждый раз, когда вносишь нативное изменение, явно пиши об этом в ответе: что именно изменилось и что нужна пересборка.
- Если в текущей задаче или ближайших запланированных (tasks.md активных изменений, следующий change из `docs/idea.md`) есть еще нативные изменения, предупреди и посоветуй собрать один раз после всех. Нативные изменения по возможности делай в начале задачи пачкой, чтобы проверять JS уже на свежей сборке.
- Не предлагай пересборку ради проверки, которую можно сделать в JS (dev-кнопки, логи, `__DEV__`-блоки).
- Локальные сборки квоту не тратят. `build:local:*` - это `eas build --local`: те же профили из `eas.json` и тот же ключ подписи из EAS, что у облачных, поэтому локальный и облачный APK ставятся поверх друг друга без потери данных. `yarn android` подписывает debug-ключом: такой APK не встанет поверх сборки из EAS (только через удаление, с потерей данных), поэтому он только для эмулятора. Пока обе EAS-сборки идут только под arm64 (`env` в `eas.json`, помечено `TODO(release)`): так release собирается быстрее; перед релизом вернуть все архитектуры. dev и preview - разные пакеты (`com.berryrise.app.dev` и `com.berryrise.app`): стоят на телефоне рядом, у каждого своя база и свой ключ подписи в EAS. Нужны JDK 17 (`brew install openjdk@17`, `JAVA_HOME` на него; JDK 25 из Android Studio валит CMake-шаг) и Android SDK (`ANDROID_HOME`), недостающие части SDK Gradle докачивает сам. Локальная сборка - основной способ, EAS - когда локально собрать нельзя (нет мака под рукой, сломалось окружение).

### Проверка на эмуляторе

Поведение в приложении проверяем сами на локальном эмуляторе скиллом `emulator-check` (`.claude/skills/emulator-check/`): скрипт `scripts/emu.py` поднимает эмулятор и dev build (пересобирает, только если поменялись нативные входы), заводит данные через SQL (`seed`), тапает по тексту, делает сжатые скриншоты, меняет тему, язык и время. Задачи "проверить на телефоне" в tasks.md закрываем так. Эмулятор - AVD `Pixel_8` на образе "Google APIs" без Play Store.

## Процесс (OpenSpec)

Фичи и заметные изменения поведения идут через OpenSpec: `/opsx:explore` (по желанию обсудить идею) → `/opsx:propose <имя>` (proposal, delta-спеки, design, tasks в `openspec/changes/<имя>/`) → `/opsx:apply` → `/opsx:archive` (delta вливается в `openspec/specs/`). Мелкие правки, багфиксы и рефакторинг без изменения поведения делаем напрямую. Темы для изменений берем из `docs/idea.md`.

CLI ставится глобально (`npm i -g @fission-ai/openspec`), телеметрия отключена через `openspec config set telemetry.enabled false` (настройка машины, не репозитория). После обновления CLI запускать `openspec update`, чтобы обновить файлы в `.claude/`.

## Конвенции

- Все записи в БД с `id` (uuid), `createdAt`, `updatedAt`, удаление мягкое через `deletedAt`, чтобы потом добавить синхронизацию.
- Стрик, экономию и достижения вычисляем, а не храним.
- Варианты ответов (итоги дня, причины, напитки) хранятся в коде ключами, тексты лежат в i18n.
- Тесты только на чистую логику: стрик, деньги, калории, условия достижений. Раннер jest с пресетом `jest-expo` (`jest.config.js`: алиас `@/`, плюс babel для `lucide-react-native`, он публикует только ESM `.mjs`, и мок `@react-native-documents/picker` в `setupFiles`: барель `shared/lib` тянет его во все тесты), потому что барели слайсов тянут React Native и `.tsx`. Проверки через `node:assert/strict`. TypeScript разделен на два проекта: корневой `tsconfig.json` держит общие опции и `paths` (их читает Metro) и ссылается на `tsconfig.app.json` (`src` без тестов, `index.ts`; `types: []`, глобалов node и jest там нет) и `tsconfig.node.json` (тесты, `app.config.ts`, `eslint.config.js`; `types: ["node", "jest"]`). `yarn typecheck` - это `tsc -b`, он проверяет оба, eslint через `projectService` сам берет нужный проект.
- ESLint (`eslint.config.js`): поверх `eslint-config-expo` идут `@eslint/js` recommended и для TS `strictTypeChecked` из `typescript-eslint` (с типами, через `projectService`). `!` запрещен: элемент по индексу, который есть по логике (цикл, по модулю длины), берем через `at(list, i)` из `shared/lib` (падает с понятной ошибкой), литералы-таблицы в сценах медалей - `as const`, остальное сужаем проверкой. Выключены `no-confusing-void-expression` и `no-floating-promises` (промисы без `await` в эффектах и обработчиках - норма, `void` не пишем; забытый `await` линтер не ловит, следим сами), у `no-misused-promises` выключен `checksVoidReturn`. Приведение типов через `as` запрещено (`consistent-type-assertions: never`, `as const` можно): вместо него `satisfies`, сужение проверкой или type guard. Строки таблиц проверяем схемами zod (`parseRows`, см. `shared/db`), JSON из `settings` и файлов - парсерами из `shared/lib` (`parseList(json, isOneOf(keys))`, `parseJson` + `isRecord`), неподходящее отбрасываем. Импорт картинок типизирован в корневом `assets.d.ts`. `if`, циклы, `switch` и `try` - всегда в скобках (`curly: all`, тело на новой строке ставит prettier) и с пустой строкой до и после (`padding-line-between-statements`), оба правила чинит `eslint --fix`. Магические числа запрещены (`@typescript-eslint/no-magic-numbers`, кроме -1, 0, 1, 2): число получает имя константой, единицу времени берем из `shared/lib`; значения полей объектов (стили, конфиги анимаций) правило не трогает, тернарник со стилями заменяем объектом вариантов. Не проверяются тесты, сцены медалей с `MedalMagic`, `Burst` и `pluralize`. Таблицы-данные (`moods`, пороги достижений) - под `eslint-disable` с причиной. `eslint-disable` - только на строку и с причиной (исключение - блок таблиц порогов в `achievements.ts`, prettier разносит его на несколько строк).
- `Button` и `Switch` из `react-native` запрещены правилом `no-restricted-imports` в `eslint.config.js`, берем свои из `@/shared/ui`. Любая кнопка - это `Button` из `@/shared/ui`, а не свой `Pressable`: нужный вид добавляем вариантом или через `children`. Свой `Pressable` - только у нажимаемых элементов, которые не кнопки: клетка календаря, плитка медали, карточка, строка `Row`, `Chip`.
- Аналитики нет. Единственный сетевой запрос - проверка OTA-обновления при запуске, без данных пользователя. Данные пользователя не покидают устройство, кроме Android Auto Backup и ручного экспорта.
- Комментарии в коде на русском. Коммиты в формате Conventional Commits.
