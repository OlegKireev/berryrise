# Design

## Context

Поля трат уже лежат в `habit` (`weeklySpendMinor`, `currency`, `drinks` как JSON `{пресет: порций в неделю}`, `naCountsAsRelapse`), но их никто не пишет и не читает. Пресеты `drinks` объявлены в `src/entities/habit/model/types.ts` с пометкой `@public`. Стрик считает чистая функция `streak()` в `src/entities/habit/model/streak.ts`, она отдает `total`. Настройки - заглушка с dev-кнопкой сброса. Онбординг после старта делает `router.dismissAll()` и `replace` на шаг причин.

## Goals / Non-Goals

**Goals:**

- Одна форма трат на онбординг и настройки.
- Расчет экономии чистой функцией с тестами, рядом со `streak`.
- Без новых зависимостей и без новой миграции.

**Non-Goals:**

- Общий механизм настроек (`settings` key/value): старт и траты живут в `habit`, ключ-значение пока не нужен.

## Decisions

### Схема: правим первую миграцию, а не добавляем вторую

В `migrations[0]` у `habit` колонка `weeklySpendMinor` переименовывается в `weeklySpend INTEGER` (целые единицы валюты), `naCountsAsRelapse` удаляется. Пользователей нет, единственная живая база - у автора, ее сбрасывает dev-кнопка в настройках или переустановка. Альтернатива - миграция v2 с `RENAME COLUMN`/`DROP COLUMN` - оставила бы в истории мусор ради базы, которую проще пересоздать. Комментарий "выпущенные миграции не меняем" остается: правило действует с первого релиза. Служебные `id/createdAt/updatedAt/deletedAt` не трогаем, `updatedAt` обновляется при каждом `UPDATE`.

Пустая сумма хранится как `weeklySpend = NULL`. Валюта сохраняется всегда, когда пользователь сохранил форму, чтобы при следующем открытии выбор не сбрасывался. `drinks` хранит только пресеты с количеством больше нуля, пустой выбор - `'{}'`.

### Целые единицы вместо минорных

Сумма - прикидка, копейки никто не вводит. Целые числа и так не дают ошибок float, а `* 100` только добавил бы преобразования при вводе и показе. Поле ввода - `keyboardType="number-pad"` с отбрасыванием всего, кроме цифр.

### `savings()` в `entities/habit/model/savings.ts`

```ts
savings(total: number, weeklySpend: number | null, drinks: Partial<Record<Drink, number>>)
  -> { money: number | null; portions: number; kcal: number }
```

Все значения `Math.floor(perWeek * total / 7)`: сначала умножение, потом деление, чтобы не терять точность на дробном "в день". Калорийность порции - константа `drinkKcal: Record<Drink, number>` в том же слайсе: пиво 0,5 - 215, бокал вина 150 мл - 125, шот 40 мл - 95, коктейль - 200. На вход идет `total` из `streak()`, поэтому срыв экономию не уменьшает. Импорты относительные с `.ts`, тест `savings.test.ts` рядом.

Альтернатива - считать от календарного времени с первого старта - противоречит тому, что за день срыва деньги потрачены.

### Форма трат - фича `features/edit-spending`

Форму используют две страницы (шаг онбординга и настройки), а страницы друг друга не импортируют. Поэтому она уходит в слой ниже. Это действие пользователя над привычкой, значит `features`, по аналогии с `delete-relapse`. Компонент `SpendingForm` принимает `habit`, подпись кнопки и `onSaved`, внутри вызывает `updateSpending(db, id, { weeklySpend, currency, drinks })` из `entities/habit`. Кнопку "Пропустить" рисует страница онбординга, форма про нее не знает.

Список валют `currencies = ['RUB', 'USD', 'EUR', 'GEL', 'KZT', 'UAH', 'BYN', 'GBP', 'TRY', 'AMD']` лежит в фиче, выбор чипами. Валюта по умолчанию: `getLocale() === 'ru' ? 'RUB' : 'USD'`.

### Формат денег: `formatMoney(amount, currency)` в `shared/i18n`

`new Intl.NumberFormat(locale, { style: 'currency', currency, maximumFractionDigits: 0 })`, кэш форматтеров не нужен: вызовов единицы. В чипе валюты показываем код и символ, символ достаем через `formatToParts` и часть `currency`. `Intl.DisplayNames` и `Intl.supportedValuesOf` не используем: в Hermes их, скорее всего, нет.

### Редактирование старта

В настройках `DateTimeField` со старта, `max = min(now, самый ранний неудаленный срыв)`. `listRelapses` уже отдает срывы по убыванию, берем последний. `DateTimeField` уже прижимает время к границам, поэтому позже срыва выбрать нельзя. Сохраняем сразу на `onChange` через `updateHabitStart(db, id, startAt)`, без отдельной кнопки: одно поле, лишняя кнопка только мешает. "Сегодня" перечитывает данные на фокусе, пересчет работает сам.

### Онбординг

`StartPage` после `createHabit` делает `dismissAll()` и `replace('/onboarding/spending')`. Новая `SpendingStepPage` показывает `SpendingForm` с подписью "Дальше" и кнопку "Пропустить", обе ведут `replace('/onboarding/reasons')`. Назад на старт не вернуться: стек сброшен, жест в группе онбординга уже выключен.

### "Сегодня"

`TodayPage` уже читает `habit` на фокусе, добавляем в состояние `weeklySpend`, `currency`, `drinks` (парсим JSON). Блок "Сэкономлено" или подсказка с `router.push('/settings')`. Формат порций - функция склонения в `shared/i18n` рядом с `days` (`portions(n)`).

## Risks / Trade-offs

- [`Intl.NumberFormat` с `style: 'currency'` в Hermes на Android может работать не полностью] → проверить на устройстве в Expo Go. Если падает или выдает код вместо символа, `formatMoney` переходит на `` `${n.toLocaleString(locale)} ${code}` ``, интерфейс не меняется.
- [Калории примерные, у разных напитков сильный разброс] → это прикидка для мотивации, в подписи значок "~".
- [Правка первой миграции ломает базу автора] → перед установкой новой версии нажать dev-кнопку сброса или переустановить приложение. Записать в описании коммита.
- [Сохранение старта на каждый `onChange`] → на Android пикер сначала дата, потом время, это две записи вместо одной. Безвредно.

## Migration Plan

Миграции нет. После обновления на устройстве автора: сброс данных dev-кнопкой, онбординг заново.
