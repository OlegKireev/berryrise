# Proposal

## Why

Все фичи MVP (счетчик, срывы, чек-ин, режим компании, причины, ачивки) хранят данные на устройстве, а базы пока нет. Схему продумали целиком заранее, чтобы фичи не противоречили друг другу. Пока приложение стоит только на телефоне автора, все таблицы создаем одной миграцией.

## What Changes

- Подключаем локальную SQLite-базу, которая открывается при старте приложения.
- Добавляем механизм миграций через `PRAGMA user_version`. Миграция v1 создает все таблицы MVP: `habit`, `relapse`, `checkin`, `party`, `reason`, `reply`, `contact`, `settings`.
- Описываем в коде TypeScript-типы строк и ключи готовых вариантов (места, трудности, помощники, настроение, тяга, напитки, причины, ответы).
- Добавляем правило целостности: при мягком удалении срыва связанная с ним вечеринка теряет результат "выпил".
- Обновляем черновик сущностей в `docs/idea.md`: `outing` переименован в `party`, таблицы `achievement` больше нет, добавлены `reply` и `contact`.

Вне скоупа:

- Экраны и сценарии, которые пишут в эти таблицы (онбординг, срыв, чек-ин, режим компании, причины, настройки). Они пойдут отдельными изменениями.
- Вычисление стрика, экономии и ачивок.
- Выбор экстренного контакта из адресной книги (`expo-contacts`). Таблица `contact` создается сейчас, пакет добавим вместе с фичей.
- Экспорт и импорт в JSON, синхронизация.
- Курение. Поле `habit.type` есть, но значения кроме `alcohol` не поддерживаются.

## Impact

- Новые зависимости: `expo-sqlite`, `expo-crypto`. Обе есть в Expo Go, development build не нужен.
- Новый модуль `src/db/` (открытие базы, миграции, типы, ключи вариантов).
- `src/app/_layout.tsx` оборачивается в провайдер базы.
- Документация: `CLAUDE.md` (структура, статус), `docs/idea.md` (черновик сущностей).
