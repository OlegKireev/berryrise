# Design

## Context

Сейчас тема - `DefaultTheme`/`DarkTheme` из React Navigation, которые прокидываются в `ThemeProvider` в `src/app/_layout.tsx`. Компоненты берут цвета через `useTheme().colors` (6 стандартных полей: `primary`, `background`, `card`, `text`, `border`, `notification`). Остального не хватает, поэтому появились хардкоды: `pages/today/ui/colors.ts` (`SOBER`, `SECONDARY`), `pages/progress/ui/statusColor.ts` (`SOBER`, `RELAPSE`), `color="red"` в `DevResetButton`. Кнопки - нативный `Button` из RN в 26 файлах, `Switch` из RN в `NotificationForm` и `ScreeningPage`. Шрифт системный.

`expo-font` уже входит в `expo` и в текущую сборку, `expo-system-ui` уже в зависимостях. Значит, шрифт и цвет корневого окна можно менять из JS без пересборки.

## Goals / Non-Goals

**Goals:**

- Одно место, где описаны все цвета обеих тем, и один хук, через который их берут компоненты.
- Свои `Button`, `Card`, `Switch` с API, близким к RN, чтобы замена была механической.
- Ничего нативного: изменение проверяется на текущем dev build.

**Non-Goals:**

- Переключатель темы в настройках (тема только по системе).
- Отступы и шкала размеров как отдельные токены: пока хватает чисел в `shared/ui` (радиус 10, отступ карточки 16). Вынесем, когда повторов станет больше.
- Перекладка экранов на `Card` там, где сейчас нет рамки: компоновка - следующий change.

## Decisions

### Токены в `shared/ui/theme.ts`, хук `useColors()`

Палитра - объект `{ light, dark }` с одинаковыми ключами:

| Токен         | Светлая   | Темная    | Где                                                |
| ------------- | --------- | --------- | -------------------------------------------------- |
| `background`  | `#F4F1EA` | `#1A1917` | фон экранов, шапок                                 |
| `card`        | `#FFFFFF` | `#23211E` | карточки, поля, таб-бар                            |
| `border`      | `#E6E0D4` | `#37342F` | рамки карточек, полей, таб-бара, пустой день       |
| `text`        | `#23211D` | `#ECE7DD` | основной текст                                     |
| `muted`       | `#7A7466` | `#A29C90` | `hint`, плейсхолдеры, тихие кнопки, неактивный таб |
| `primary`     | `#2A2824` | `#ECE7DD` | главная кнопка, выбранный чип                      |
| `onPrimary`   | `#F4F1EA` | `#1A1917` | текст на главной                                   |
| `secondary`   | `#D9E1D5` | `#2D3631` | второстепенная кнопка                              |
| `onSecondary` | `#34504C` | `#BFD0C3` | текст на второстепенной, включенный `Switch`       |
| `sober`       | `#6E8F6A` | `#7FA27A` | трезвый день                                       |
| `relapse`     | `#C08A5B` | `#C99A6E` | срыв                                               |

Темная - пара по тем же принципам: теплый почти черный фон, карточка чуть светлее фона, главная кнопка инвертирована (светлая на темном), рамки вместо теней. Значения темной стартовые, их подкручиваем на устройстве в рамках задачи.

`useColors()` берет схему из `useColorScheme()` и отдает нужную палитру; `null` от системы - светлая. Тему навигации через `useTheme()` не используем: на устройстве экраны и вложенные навигаторы получали ее только при монтировании и смену темы не видели (проверено dev-замером: `useColorScheme` в экране обновлялся, `useTheme().dark` оставался `false`). Поэтому шапки, фон экранов и таб-бар красим явно: `useScreenColors()` отдает `headerStyle`, `headerTintColor`, `headerTitleStyle`, `contentStyle`/`sceneStyle`, их раскладывают в `screenOptions` все три layout.

Альтернатива - расширить тему React Navigation своими полями и читать через `useTheme()`. Отказались: тип `Theme` придется расширять через module augmentation, а сам React Navigation из лишних полей ничего не использует.

### React Navigation получает тему, собранную из токенов

`navigationTheme(scheme)` в `shared/ui/theme.ts` собирает `Theme` для `ThemeProvider`: `background`, `card` (= `background`, чтобы шапка сливалась с экраном), `text`, `border`, `primary`, `notification` (= `relapse`) и `fonts` с Manrope по начертаниям. Так шапки стека, заголовки модалок и подписи табов получают цвета и шрифт без настройки каждого экрана. Сверху в `screenOptions` корневого `Stack`: `headerShadowVisible: false`. В таб-баре: `tabBarStyle` с фоном `card` и верхней рамкой `border`, активный таб `text`, неактивный `muted`. Шестеренка (`⚙︎`) цвета `muted`.

Цвет корневого окна Android ставим через `SystemUI.setBackgroundColorAsync(background)` при смене схемы, чтобы при переходах не мелькал белый или черный фон.

### Шрифт: `@expo-google-fonts/manrope` и `useFonts` в корневом layout

Пакет отдает ttf как ассеты Metro, `useFonts` из этого же пакета (обертка над `expo-font`) грузит их в рантайме. Пересборка не нужна. Грузим 4 начертания: 400, 500, 600, 700. Пока шрифты не загрузились, корневой layout рендерит `null` (локальные ассеты, это десятки миллисекунд).

На Android кастомный шрифт не подбирает начертание по `fontWeight`: нужно указывать `fontFamily` конкретного начертания (`Manrope_600SemiBold`). Поэтому `fontWeight` в коде не пишем. `Text` задает семейство через вариант и проп `weight` (`regular | medium | semibold | bold`), остальные компоненты рендерят текст через `Text`. Места, где сейчас стоит `fontWeight` в стилях, переводим на `weight`.

`expo-font` прямой зависимостью не ставим: сами его не импортируем, он приходит с `expo`. `npx expo install` для него дописывает в `app.json` плагин `expo-font`, это нативное изменение, поэтому не нужно.

Альтернатива - вшить шрифт config plugin'ом `expo-font`: шрифт доступен сразу, без загрузки. Отказались: это нативное изменение и пересборка, а выигрыш - десятки миллисекунд при старте. Вернемся к нему, если появится мигание.

### Компоненты `shared/ui`

- `Button`: пропы `title`, `onPress`, `variant: 'primary' | 'secondary' | 'quiet'` (по умолчанию `secondary`), `disabled`, `style`. `primary` и `secondary` - залитые плашки с радиусом 10, отступы 13 по вертикали, текст `semibold` 15. `quiet` - текст `muted` с подчеркиванием, без фона. `disabled` - прозрачность 0.4. Проп `title` как у RN `Button`, чтобы замена была механической. `Pressable` с `android_ripple` в цвет текста кнопки.
- `Card`: `View` с фоном `card`, рамкой 1 `border`, радиусом 10, отступом 16 и `gap` 8.
- `Switch`: RN `Switch` с `trackColor` (`border` / `onSecondary`) и `thumbColor` (`muted` выключен / `secondary` включен), чтобы кружок не сливался с фоном в темной теме.
- `Text`: цвет `text`, `hint` теперь цвет `muted` вместо прозрачности, семейство Manrope по варианту.
- `Input`: фон `card`, рамка `border`, радиус 10, плейсхолдер `muted`, шрифт Manrope.
- `Chip`: выбранный - `primary`/`onPrimary`, невыбранный - рамка `border` на `card`.

Чтобы RN `Button` и `Switch` не вернулись, в `eslint.config.js` добавляем `no-restricted-imports` на `Button` и `Switch` из `react-native` (кроме самого `shared/ui/Switch.tsx`).

### Как раскладываем существующие кнопки по видам

Правило: одна главная на экран - основное действие экрана; остальные действия - второстепенные; отмена, пропуск, удаление и срыв на "Сегодня" - тихие.

| Где                                                       | Главная            | Второстепенная                       | Тихая        |
| --------------------------------------------------------- | ------------------ | ------------------------------------ | ------------ |
| "Сегодня"                                                 | "Иду в компанию"   | итоги дня, "Укажи траты" в `Savings` | "Срыв"       |
| `PartyCard` (вместо кнопки компании)                      | "Без алкоголя"     | "Выпил", "Открыть"                   | "Не пошел"   |
| Онбординг (все шаги)                                      | "Далее" / "Начать" | -                                    | "Пропустить" |
| Итоги дня, срыв, траты, режим компании                    | "Сохранить"        | -                                    | -            |
| `DateTimeField`, `TimeField`, `AddField`                  | -                  | все                                  | -            |
| `MonthNav`                                                | -                  | стрелки "‹" "›"                      | -            |
| Удаление (причины, ответы, срыв)                          | -                  | -                                    | все          |
| Настройки: "Открыть системные настройки", `AutostartHint` | -                  | все                                  | -            |
| Dev-кнопки (`DevResetButton`, `DevNotificationDebug`)     | -                  | -                                    | все          |

Ответы "Без алкоголя" / "Выпил" раньше различались зеленым и красным. Теперь различаются видом кнопки: красный для срыва противоречит `app-theme`.

## Risks / Trade-offs

- [Темная палитра подобрана без устройства] → Значения стартовые, задача на проверку обеих тем на телефоне с правкой токенов.
- [Где-то `fontWeight` останется и на Android даст системный bold поверх Manrope] → Поиск по `fontWeight` в `src` в задаче, после замены его там быть не должно.
- [Первый кадр пустой, пока грузятся шрифты] → Локальные ассеты, задержка незаметна. Если будет мигать - вшить шрифт плагином при ближайшей нативной пересборке.
- [Заметно меняется вид всех экранов, можно что-то сломать в раскладке (ширина кнопок, `ButtonPair`)] → `Button` принимает `style`, `PartyCard` передает `flex: 1`; проход по всем экранам в обеих темах в последней группе задач.
- [`DateTimePicker` останется системным и может не совпасть по цветам] → Осознанно: системный picker по `idea.md`.
