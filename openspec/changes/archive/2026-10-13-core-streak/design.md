# Design

## Context

Навигация и схема БД уже есть (см. `openspec/specs/local-data`), но в базу никто не пишет. Таблицы `habit` и `relapse` подходят без изменений. Тестового раннера в проекте нет. Требования - в `specs/` этого change.

## Goals / Non-Goals

**Goals:**
- Минимум кода и зависимостей: всё работает в Expo Go.
- Логика стрика - одна чистая функция без React Native, покрыта тестом.

**Non-Goals:**
- Общий слой данных, хуки-репозитории, стейт-менеджер: запросы пишем прямо в экранах через `useSQLiteContext()`.
- Свои компоненты UI сверх совсем простых (чипы выбора).

## Decisions

### Онбординг завершен = есть привычка

Отдельный флаг в `settings` не заводим. Строка `habit` создается только на последнем шаге онбординга, поэтому ее наличие и значит "онбординг пройден". Прерванный онбординг ничего не пишет и начинается сначала. Когда появятся шаги 4-7, их ответы так же собираются в памяти и пишутся одной транзакцией в конце, правило останется верным.

Альтернатива - флаг `onboarded` в `settings`. Это второй источник правды, который может разойтись с `habit`.

### Роутинг

- `src/app/onboarding/_layout.tsx` - свой `Stack`, внутри `index` (дисклеймер), `screening`, `warning`, `start`. Ответы скрининга передаются только как переход на `warning`, нигде не хранятся.
- В корневом `Stack` экран `onboarding` без заголовка и без жеста назад.
- Проверка в `src/app/(tabs)/_layout.tsx`: читаем `SELECT id FROM habit WHERE deletedAt IS NULL LIMIT 1`. Пока идет запрос, рендерим `null`. Если строки нет, рендерим `<Redirect href="/onboarding" />`.
- `start` после вставки делает `router.replace('/')`.

### Стрик - чистая функция

`src/streak.ts`: `streak(startAt: number, relapseAts: number[], now: number) => { current, best, total, since }`, где `since` - момент начала текущей серии (старт или последний срыв). Работает на локальных датах через `Date`: идем по дням от дня старта + 1 до сегодня, день трезвый, если в нем нет срыва (`Set` ключей `YYYY-MM-DD`). Сложность O(дней), для лет истории это тысячи итераций - ок.

Шаг по дням через `setDate(d + 1)`, а не через `+ 86_400_000`: так переход на летнее время не ломает подсчет.

### Тест без Jest

Node 24 сам снимает типы с `.ts`, поэтому тест - `src/streak.test.ts` на `node:test` и `node:assert`, скрипт `"test": "TZ=Europe/Berlin node --test 'src/**/*.test.ts'"` (фиксированная зона с переходом на летнее время, чтобы тест DST был детерминированным). Чтобы импорт `./streak.ts` прошел `tsc`, в `tsconfig.json` включаем `allowImportingTsExtensions` (с `noEmit` это разрешено). Типы `node:test` дает `@types/node` в devDependencies, подключенный через `/// <reference types="node" />` в самом тесте: TS 6 не подхватывает `@types` автоматически. `streak.ts` не импортирует ничего из React Native и пишется только на стираемом синтаксисе (без `enum`). Даты в тесте создаем через `new Date(y, m, d, h, min)`, поэтому от часового пояса машины тест не зависит.

Альтернатива - `jest-expo`: тяжелый пресет и конфиг ради одной функции.

### Обновление данных

"Сегодня" и "Прогресс" загружают данные в `useFocusEffect`: после закрытия модалки срыва экран снова получает фокус и перечитывает базу. Смена дня: на "Сегодня" таймер до ближайшей полуночи, который запускает пересчет. Так не нужен `addDatabaseChangeListener`.

### Выбор даты и времени

`@react-native-community/datetimepicker`, ставим через `npx expo install`. Пакет входит в Expo Go. На Android пикер открывается императивно (`DateTimePickerAndroid.open`): сначала дата, потом время. Границы задаем через `minimumDate`/`maximumDate`. Время пикер не ограничивает, поэтому после выбора проверяем, что значение в допустимых границах, и если нет, прижимаем к границе. На iOS используем компонент `DateTimePicker` с `mode="datetime"`. Это не наша цель, но и ломаться там ничего не должно.

### Склонение "день"

В `src/i18n.ts` добавляем `days(n)` с правилом склонения руками: в Hermes нет `Intl.PluralRules` (`Intl.DateTimeFormat` есть).

### Разбор срыва

Чипы - `Pressable` с текстом, выбранный подсвечивается `colors.primary`. Значения пишутся в существующие колонки `relapse`: `mood`, `places` и `hardships` как JSON-массив или `NULL`, если ничего не выбрано, `note` - `NULL` для пустой строки. Подписи ключей `moods`, `places`, `hardships` из `src/db/keys.ts` кладем в i18n под ключами вида `place_home`, их переиспользует чек-ин.

### Удаление срыва

`Alert.alert` с подтверждением, потом `deleteRelapse` из `src/db/records.ts`, потом перечитать список.

### БД

Схема не меняется, миграций нет. Новые строки создаются через `newRow()`. `habitId` срыва - id единственной привычки.

## Risks / Trade-offs

- [Время срыва раньше старта или в будущем через пикер времени] → прижимаем к границе после выбора и показываем итоговое значение.
- [Таймер полуночи не сработает, если приложение было в фоне] → `useFocusEffect` и возврат из фона все равно пересчитывают. Для фона добавим `AppState`-подписку, только если на практике всплывет.
- [Пользователь ошибся со стартом, а редактирования нет] → в этом change не решаем, редактирование старта идет в куске "Настройки". Пока это можно исправить переустановкой.
- [Изменение `tsconfig.json`] → флаг влияет только на проверку типов, Metro его не читает.
