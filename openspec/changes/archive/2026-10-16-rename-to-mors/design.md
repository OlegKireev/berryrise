# Design

## Context

Мотивация - в proposal.md. Старое название живет в трех местах разного рода:

- нативные поля `app.json`: `name`, `slug`, `scheme`, `android.package`, `ios.bundleIdentifier`, иконка и сплэш;
- код: имя базы в `src/app/_layout.tsx`, маркер и имя файла в `src/features/backup/model/format.ts`, строки i18n в `backup`, `notifications` и `onboarding`;
- инструменты и документы: `package.json`, `emu.py`, `SKILL.md`, README, CLAUDE.md, `docs/idea.md`, спеки.

Иконка рисуется SVG в `assets/src/` (холст 108), PNG собирает `yarn icons`. Сейчас у adaptive icon фон сплошной (`backgroundColor: #34504C`), а знак лежит в foreground, уменьшенный на 2/3. Превью выбранного варианта E5 и точные градиенты - в `icons.html` из сессии explore. Переносим из него цвета, а не код.

## Goals / Non-Goals

**Goals:**

- Все нативные правки в одной пересборке.
- Автор переносит свою историю из старого приложения без потерь.

**Non-Goals:**

- Перенос базы между package на уровне файлов (adb, run-as): для этого есть экспорт и импорт.
- Изменение формата файла экспорта, кроме значения маркера.

## Decisions

### Маркер резервной копии: новый пишем, оба принимаем

`APP = 'com.berryrise.app'` пишется в новые файлы. `parseBackup` принимает `APP` и `LEGACY_APP = 'dev.olegkireev.quit'`, рядом комментарий: удалить после переноса данных автора. Отдельной версии формата не заводим: обертка та же, отличается только строка.

Альтернатива - принимать любой `app`. Отвергнута: тогда пропадает проверка "это не наш файл", а она есть в спеке.

### Имя базы меняется без миграции

`databaseName="berryrise.db"`. С новым package приложение ставится с пустым хранилищем, и старого `resheno.db` рядом нет, так что переносить нечего. Если сменить имя базы при старом package, данные бы потерялись. Поэтому имя базы и package меняются в одном релизе, вместе.

### Иконка: фон adaptive icon отдельным слоем

Фон с градиентом нельзя задать через `backgroundColor`, поэтому добавляется `assets/src/android-icon-background.svg`, а в `app.json` используется `adaptiveIcon.backgroundImage`. Слои:

- **background** (108): заливка `#1C1A18` и радиальное свечение `#8E3040` (opacity .85 -> 0). Знак в foreground уменьшен на 2/3 к центру, поэтому свечение пересчитывается под уменьшенную ягоду: центр по y ≈ 51.3 из 108 (cy ≈ .475), радиус ≈ .55 · 2/3 от холста. Иначе ореол съедет относительно ягоды.
- **foreground**: ягода с радиальным градиентом (`#F7798A` -> `#E0475B` на .6 -> `#A82E43`, cx .38, cy .36, r .75), блик (белый, opacity .35), хвостик и линия горизонта `#F4F1EA`, нижние линии `#E0475B` (opacity .75 и .5).
- **monochrome**: тот же силуэт, ягода, хвостик и линии белым. Блик не нужен: белое на белом все равно не видно.
- **icon.svg** (iOS): фон и свечение на весь квадрат, знак без уменьшения (как в превью).
- **splash-icon.svg**: медальон r=36 с той же заливкой и свечением, знак уменьшен на 2/3.

`yarn icons` получает пятый файл в списке. Фон сплэша в `app.json` (`#F4F1EA` / `#1A1917`) не меняется: это цвета темы, а не иконки.

Альтернатива - оставить сплошной `backgroundColor: #1C1A18` без свечения. Отвергнута: именно свечение отделяет иконку от темных обоев, ради этого вариант и выбирали.

### slug: переименовать проект на expo.dev

EAS сверяет `slug` из `app.json` с проектом по `extra.eas.projectId`, при несовпадении `eas build` падает. Проект `resheno` переименовывается на expo.dev в `berryrise` вручную, `projectId` остается прежним. Если переименование недоступно, запасной путь - убрать `projectId` и сделать `yarn eas init`, создав новый проект: историю сборок не жалко, ключи все равно новые.

### Ключ подписи для нового package

Ключи EAS привязаны к application id, поэтому для `com.berryrise.app` их нет. Первую сборку запускаем интерактивно (или сначала `yarn eas credentials`), чтобы EAS сгенерировал keystore. Дальше `build:local:*` и облачные сборки используют его и ставятся поверх друг друга, как раньше.

## Risks / Trade-offs

- [Старое приложение остается на телефоне и тоже шлет уведомления] -> в шаге переноса удалить его сразу после успешного импорта.
- [Экспорт из старого приложения сделан не до конца или потерян] -> перед удалением старого убедиться, что в новом виден тот же стрик и календарь.
- [`exp+berryrise://` не откроется в старом dev build на эмуляторе] -> на эмуляторе снести `dev.olegkireev.quit`; `emu.py` пересоберет dev build по новым нативным входам.
- [Неинтерактивная локальная сборка не найдет ключи] -> первая сборка интерактивная, см. решение выше.
- [Свечение на фоне adaptive icon не совпадет с ягодой на конкретной маске лаунчера] -> проверить на эмуляторе в круге и скругленном квадрате, при расхождении поправить центр в `android-icon-background.svg`.

## Migration Plan

1. На телефоне в старом "Решено": "Экспорт и импорт" -> "Сохранить на телефон" (файл `resheno-...json` в Download).
2. Поставить новую сборку `com.berryrise.app`. Она встает рядом со старой, а не поверх.
3. В новом приложении на первом шаге онбординга нажать "Восстановить из файла" и выбрать этот файл.
4. Проверить стрик, календарь и причины, затем удалить старое приложение.
5. Когда перенос сделан, убрать `LEGACY_APP`. Сделано в этом же change: автор перенес данные до архивации, поэтому в главные спеки прием старого маркера не попадает.

Откат: старое приложение не трогаем, пока не пройден шаг 4.
