# Design

## Context

Достижения вычисляются в `useProgress` (`pages/progress`): история из пяти сущностей, `soberDays`, `achievements`, `medalStates`. Момента получения в данных нет. `Medal` (`entities/habit/ui`) - статичный SVG, тапа у `MedalTile` нет. В сборке нет Reanimated, Skia и Lottie; есть `Animated` из React Native, `react-native-svg` и неиспользуемый пока `expo-haptics`. В `settings` уже лежат JSON-значения по ключу (`notifications`, `customPartyDrinks`), `docs/idea.md` заранее предусматривает там "показанные достижения".

## Goals / Non-Goals

**Goals:**

- Одна карточка медали на оба случая: тап и празднование, разница только во входе и кнопках.
- Решение "что праздновать" - чистая функция с тестом.
- Без нативных изменений и пересборки.

**Non-Goals:**

- Анимация в UI-потоке. Для одной медали на экране JS-поток справляется.
- Общий слой "событий" для других праздников (майлстоуны и т.п.).

## Decisions

### Анимация: `Animated` + `react-native-svg`, без новых библиотек

Слои эффекта:

- **Свечение** - `View` под медалью с радиальным градиентом в SVG, пульсирует `opacity` и `scale` (`useNativeDriver`).
- **Блик** - внутри SVG медали: группа с `ClipPath` по внешнему контуру рамки (контур уже есть в `frames.tsx`), в ней наклонная полоса с `LinearGradient` от прозрачного к белому и обратно. Полоса едет по `x` раз в ~3 секунды: `Animated.Value` со слушателем, который кладет значение в state маленького компонента `Shine`. SVG-атрибуты нативный драйвер не умеет, а `Animated.createAnimatedComponent(Rect)` с JS-драйвером на Fabric пропсы SVG не обновляет (проверено на эмуляторе).
- **Пыль** - 10-14 маленьких `View` (точки и четырехлучевые искры из двух полосок) поверх медали, у каждой своя случайная стартовая точка, задержка и длительность (считаются один раз в `useMemo`); всплывают, мерцают и гаснут в `Animated.loop`, нативный драйвер. Цвет пыли по металлу рамки (бронза теплая, платина холодная).
- **Вход** - вспышка (белый круг: `scale` растет, `opacity` гаснет), медаль растет из 0 пружиной `Animated.spring`, 16-20 частиц разлетаются по кругу и гаснут. Вибрация `Haptics.notificationAsync(Success)` в начале входа.

Альтернативы: Skia дала бы настоящие шейдеры фольги и шума, Reanimated - плавность в UI-потоке. Обе - нативные зависимости с пересборкой, Skia еще и второй способ рисовать медали. Если `Animated` не хватит по виду или плавности, следующим шагом идет Skia отдельным изменением.

Все это лежит в `entities/habit/ui`: `MedalMagic` (свечение, пыль, вход вокруг `Medal`) и проп `shine` у `Medal`, который включает блик внутри SVG (ему нужен контур рамки). Страница эффектов не знает, она рендерит `<MedalMagic achievement state entrance />`.

Уменьшение движения: `AccessibilityInfo.isReduceMotionEnabled()` и подписка на `reduceMotionChanged`, маленький хук рядом с `MedalMagic`. При включенном - медаль статична, вибрация остается.

### Карточка: один роут `achievement/[key]`, прозрачная модалка

`presentation: 'transparentModal'`, без шапки: темная подложка поверх текущего экрана, медаль по центру, тап по подложке или кнопка закрывает. Параметры: `key`, `celebrate=1` (вход и подпись "Новое достижение"), `queue` (остальные ключи очереди через запятую). "Дальше" делает `router.setParams` со следующим ключом, как листание дней в `day/[date]`: "назад" закрывает карточку сразу. `MedalMagic` получает `key={achievement}`, чтобы вход проигрался заново.

Страница `AchievementPage` - четвертая в `pages/progress`, данные из `useProgress` (там уже `got` и `states`), как у `DayPage` и `AchievementsPage`. `MedalTile` получает `onPress`, переход делают `Achievements` и `AchievementsPage`.

Альтернатива - обычная `modal` с шапкой, как у дня. Отказались: празднованию нужна сцена на темном фоне, а не лист с заголовком.

### Расчет медалей переезжает в фичу

Проверку новых зовут две страницы ("Сегодня" и "Прогресс"), а страницы друг друга не импортируют. Поэтому загрузка истории и расчет из `useProgress` переезжают в `features/celebrate-achievement/api/achievements.ts` (`loadAchievements(db, now)`), `useProgress` зовет его. Фича трогает пять сущностей, это ее уровень.

### Что праздновать: чистая `model/celebrate.ts`

```
celebrate(got, seen | null, relapseToday) -> { show, seen }

seen == null      -> show [],  seen = все полученные   (первый запуск)
relapseToday      -> show [],  seen без изменений      (откладываем, не забываем)
иначе             -> show = полученные минус seen, в общем порядке
                     seen = (seen ∩ полученные) ∪ show
```

Пропавшие медали выпадают из `seen` только в третьей ветке: ошибочный срыв, записанный и удаленный в тот же день, не вызывает повторный праздник. Медали очереди сразу попадают в `seen`, до показа: закрытая посреди очередь не повторяется. Тест рядом, файл импортирует только тип `AchievementKey` относительным путем (`import type` стирается, node его не грузит).

`seen` хранится JSON-массивом ключей в `settings` под ключом `seenAchievements` (`api/seen.ts`, по образцу `features/notifications/api/prefs.ts`). Миграция не нужна: таблица `settings` есть, отсутствие строки и есть "первый запуск".

"Срыв сегодня" - новый запрос в `entities/relapse`: есть неудаленный срыв, у которого `at` или `createdAt` в границах сегодняшнего дня (`dayRange(toDay(now))`). `createdAt` ловит срыв, записанный сегодня задним числом.

### Где проверяем

`useCelebrate()` в фиче отдает `check()`: грузит медали и `seen`, считает `celebrate`, пишет `seen`, если поменялся, и при непустом `show` открывает `/achievement/<show[0]>?celebrate=1&queue=...`. Вызовы:

- `useFocusEffect` на `TodayPage` и `ProgressPage`: открытие приложения, возврат после итогов дня, модалки срыва, карточки дня (удаление срыва). Пока открыта карточка, табы не в фокусе; после закрытия повторная проверка ничего не найдет, `seen` уже записан.
- после ответа на вечеринку в `useToday` (`afterParty`): фокус не меняется.

Повторный вызов, пока идет предыдущий, пропускаем флагом в модуле: двойной фокус не откроет две карточки.

## Risks / Trade-offs

- [Блик через JS-драйвер дергается, когда JS занят] → карточка - отдельный экран без тяжелой работы; если видно - Skia отдельным изменением.
- [Празднование открывается в неудобный момент, например при открытии из уведомления итогов дня] → проверка только на табах, а модалки (итоги, срыв) открываются поверх и закрываются раньше.
- [Пользователь не понял, что медаль за прошлое (отложенная или задним числом)] → в карточке дата получения, не "сегодня".
- [Обновление на устройстве без `seenAchievements`, но с медалями] → первая проверка молча записывает все полученные.

## Migration Plan

Схема не меняется. Нативных изменений нет: `expo-haptics` уже в сборке, роут и анимации - JS. Откат - удалить код, ключ `seenAchievements` в `settings` никому не мешает.
