# Proposal

## Why

После релиза в Google Play критичный баг придется чинить через новую версию в сторе, а новое приложение люди обновляют редко и долго. OTA-обновления JS-бандла позволяют доставить исправление за часы. Подключать нужно до первого релиза: OTA получат только сборки, в которых уже есть `expo-updates`.

## What Changes

- Подключаем `expo-updates` и EAS Update. Бандл остается внутри APK. При запуске приложение проверяет сервер, скачивает новый бандл в фоне и применяет его при следующем запуске. Если новый бандл падает на старте, приложение откатывается на предыдущий.
- **BREAKING (для принципа приватности)**: приложение при запуске делает один анонимный сетевой запрос к серверу обновлений. Данные пользователя по сети по-прежнему не уходят.
- `runtimeVersion` с политикой `fingerprint`: бандл приходит только на сборки с совпадающей нативной частью.
- Каналы: в dev-сборке OTA нет. Preview слушает канал `preview`, новая production-сборка - канал `production`. Порядок публикации: сначала `preview`, после проверки то же обновление промоутится в `production`.
- Миграции базы только аддитивные. Старый JS после отката не падает на базе с версией схемы выше своей.
- В журнал при первом запуске нового бандла пишется событие с его id.
- В "О приложении" рядом с версией видно id и дату установленного обновления.
- Скрипты публикации и промоута в `package.json`, описание процесса в README и CLAUDE.md, правка формулировки "без сети" в CLAUDE.md и `openspec/config.yaml`.

Вне рамок:

- iOS: конфигурация общая, но публикуем и проверяем только Android.
- Принудительная перезагрузка сразу после скачивания и критичные обновления "прямо сейчас".
- Крэш-репорты и любая телеметрия (Sentry и подобное).
- Свой сервер обновлений вместо EAS Update.
- Постепенная раскатка на часть пользователей.
- Подпись обновлений (code signing): в EAS Update она только на платном тарифе. Защита - HTTPS и 2FA на аккаунте Expo.
- Выпуск в Google Play и политика приватности для стора (делается при релизе, тут только пометка в чеклисте).

## Capabilities

### New Capabilities

- `app-updates`: доставка обновлений JS-бандла по сети: проверка при запуске, применение при следующем запуске, откат упавшего бандла, совместимость с нативной частью, каналы.

### Modified Capabilities

- `local-data`: исключение для запроса обновлений в требовании "данные только на устройстве"; старый код терпит базу с версией схемы выше своей (откат бандла).
- `settings`: "О приложении" показывает id и дату установленного обновления.
- `error-log`: событие о запуске нового обновления.

## Impact

- Зависимость `expo-updates` (нативная, через `npx expo install`). Нативное изменение: поля `updates` и `runtimeVersion` в `app.json`, каналы в `eas.json`. Нужна пересборка dev и preview.
- Новый профиль `production` в `eas.json`.
- `src/shared/db/migrations.ts` (поведение `migrate` при версии выше известной), `src/pages/settings` (AboutPage, i18n), `src/shared/lib/logEntries.ts` (тег `updates`), место записи события при старте.
- Документы: README, CLAUDE.md, `openspec/config.yaml`.
