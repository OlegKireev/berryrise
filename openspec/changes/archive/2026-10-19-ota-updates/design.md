# Design

## Context

`expo-updates` в проекте нет, JS-бандл зашит в APK. EAS-проект уже заведен (`extra.eas.projectId` в `app.json`, `owner: flucky`), профили в `eas.json`: `development` (пакет `com.berryrise.app.dev` через `APP_VARIANT` в `app.config.ts`) и `preview` (`com.berryrise.app`). Профиля `production` нет. `.gitignore` игнорирует все `*.pem`. Журнал - файл `Paths.document/app.log` (`shared/lib/log.ts`), `index.ts` при старте зовет `trimLog()`. `migrate` применяет `migrations.slice(user_version)`: на базе с версией выше известной срез пустой, миграций нет, падения нет. Это поведение уже нужное, его надо закрепить.

## Goals / Non-Goals

**Goals:**

- Минимум своего кода: проверку, скачивание, применение и откат делает `expo-updates` сам, по настройкам из `app.json`.
- Один нативный шаг: все поля `updates`, `runtimeVersion`, каналы и сертификат вносятся вместе, пересборка одна.

**Non-Goals:**

- Свой UI про обновления (баннер "доступно обновление", кнопка "обновить").
- `useUpdates`, ручные `checkForUpdateAsync`/`fetchUpdateAsync`.

## Decisions

**Автоматическая проверка, без JS-кода.** `updates.checkAutomatically: "ON_LOAD"` и `fallbackToCacheTimeout: 0` (оба значения по умолчанию, пишем явно). При запуске библиотека сама проверяет и качает бандл в фоне, применяет при следующем запуске, откатывает бандл, упавший на старте. Альтернатива - ручная проверка через `useUpdates`. Она нужна для "обновить сейчас", а это вне рамок.

**`runtimeVersion: { policy: "fingerprint" }`.** Хэш нативных входов считает Expo. Альтернатива `appVersion` требует помнить поднимать версию при каждом нативном изменении, а ошибка здесь означает падение у всех. Цена: fingerprint иногда меняется без реальной несовместимости, тогда фикс выйдет только через стор. `app.config.ts` для dev меняет пакет и имя, поэтому fingerprint у dev и preview разный. Это нормально.

**Dev без OTA.** В `app.config.ts` при `isDev` ставим `updates.enabled: false`. JS dev-сборке отдает dev-сервер, сетевой запрос к EAS ей не нужен.

**Каналы через профили `eas.json`.** `preview.channel: "preview"`. Новый профиль `production` с `channel: "production"` (`android.buildType: "app-bundle"` под Play, то же `env` с `TODO(release)`). Скриптов сборки production пока не добавляем: это релиз, вне рамок. Публикация: `eas update --channel preview`. Промоут проверенного бандла в production - `eas update:republish` той же группы в ветку `production`, без пересборки JS. Так в production попадает ровно проверенный бандл.

**Без подписи обновлений.** Code signing в EAS Update доступен только на платных тарифах (проверено: публикация с подписью на бесплатном аккаунте отклоняется). Платный тариф ради одного приложения дорог, свой сервер - больше работы, чем стоит сейчас. Защита: HTTPS до EAS и 2FA на аккаунте Expo. Вернуть подпись можно только новой сборкой (сертификат вшивается в нее), так что решение стоит пересмотреть до релиза, если появится свой сервер или платный тариф.

**Экспорт в `.expo/update`.** `eas update` по умолчанию экспортирует в `dist/` и очищает ее, а там лежат APK из `build:local:*`. Скрипт передает `--input-dir .expo/update`.

**Событие в журнале - синхронно в `index.ts`.** `logUpdateLaunch()` в `shared/lib/updates.ts`, рядом с `trimLog()`. Берет `Updates.updateId` (или "встроенный" при `isEmbeddedLaunch`) и `isEmergencyLaunch`, сравнивает с id прошлого запуска из файла `Paths.document/update-id` и при отличии пишет `log('updates', ...)` и новый id. Файл, а не `settings` в SQLite: `settings` уходит в экспорт и возвращается импортом, а прошлый бандл - свойство устройства. Ошибки проверки обновления не пишем: без сети они бывают на каждом запуске, и журнал заполнился бы шумом. Новый тег `updates` в `LogTag`.

**"О приложении".** `currentUpdate()` в том же `shared/lib/updates.ts`: `null` для встроенного бандла, иначе первые 8 символов `updateId` и `createdAt`. Страница показывает его рядом с версией через `formatDate`. Это константы процесса, хук не нужен.

**Миграции.** В `migrate` комментарий, что версия выше известной - штатный случай после отката, и правило аддитивных миграций в CLAUDE.md. Своего кода не прибавляется.

## Risks / Trade-offs

- [Взлом аккаунта Expo] → чужой бандл у всех пользователей, подписи нет. 2FA на аккаунте, при утечке - сменить доступ и republish последней хорошей группы.
- [Бандл ломает экран, но не старт] → автооткат не сработает. Откат вручную: `republish` предыдущей группы. Узнаем по журналу от пользователя.
- [Fingerprint изменился без причины] → OTA не доходит до уже установленных сборок. Перед публикацией сравнивать `runtimeVersion` бандла с runtime сборки в сторе (`eas update` показывает его).
- [Неаддитивная миграция в OTA] → старый код падает после отката. Правило в CLAUDE.md, ревью миграций.
- [Лимит бесплатного тарифа EAS Update по числу пользователей] → при росте платный тариф или свой сервер. Клиент меняет только URL.
- [Google Play] → обновлять JS разрешено, если назначение приложения не меняется. Крупные функции выпускаем через стор.

## Migration Plan

1. Пересобрать preview и dev с `expo-updates` (`yarn build:local:preview`, `yarn build:local:dev`), поставить на телефон.
2. Опубликовать тестовое обновление в `preview`, убедиться, что после второго запуска оно применилось (строка в "О приложении", запись в журнале).
3. Production-сборка с `expo-updates` - первая версия в Google Play.
